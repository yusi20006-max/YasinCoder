# YasinCoder Terminal UI\n\nThe Terminal UI (TUI) is the prompt-first command center for YasinCoder in Termux and normal interactive terminals. It is inspired by modern coding-agent interaction patterns without copying any product branding or proprietary implementation.\n\n## Launch\n\n```bash\nyasincoder tui\n```\n\nAfter installation, the dedicated launcher is also available:\n\n```bash\nyasincoder-tui\n```\n\n## Prompt-first workflow\n\nThe UI opens directly on a command prompt. You can type a coding task and press `Enter` to send it to the existing autonomous command. When the prompt is empty, `↑`/`↓` selects quick actions and `Enter` activates the highlighted action.\n\n```text\nYASIN CODER  Command\nProject: /path/to/project\nProvider: gemini   Model: gemini-3.8-flash\n────────────────────────────────────────\n\n❯ What would you like to do?\n\n↑↓ Actions/history   Enter Send   Esc Cancel   Ctrl+P Commands   Ctrl+C Exit\n```\n\nThe exact project, provider, model, width, and status values are read from the existing runtime state. The UI never invents provider credentials, test results, Git state, or session records.\n\n## Keyboard controls\n\n- `↑` / `↓` — move through quick actions when the prompt is empty; browse task history when available.\n- `Enter` — submit a typed task or activate the highlighted action.\n- `Esc` — cancel the current prompt or close the command palette.\n- `Ctrl+P` — open the command palette.\n- `Ctrl+C` / `Ctrl+D` — exit safely.\n- `←` / `→` — move the text cursor.\n- `Backspace` — edit normally.\n\nTerminal input is handled with the Python standard library. Raw terminal mode is restored in a `finally` block when an exception or exit occurs.\n\n## Command palette\n\nThe palette keeps existing actions accessible without a numbered menu:\n\n- Start a coding task\n- Inspect project\n- Choose provider/model\n- Inspect Git changes\n- Run tests\n- System status\n- Sessions\n- Settings\n- Dashboard\n- Quit\n\nThe TUI does not implement a separate agent or provider layer. Tasks still delegate to the existing `AutonomousCommand`, and provider setup remains the responsibility of `yasincoder setup`.\n\n## Termux behavior\n\nThe implementation has no third-party UI dependency. This keeps installation and startup small for native ARM64 Termux. Terminal size is read on each screen, content is clipped to the available width, and ANSI color is disabled automatically for redirected output, dumb terminals, or `NO_COLOR`.\n\n## Plain/non-interactive fallback\n\nWhen stdin or stdout is not a TTY, the UI does not attempt raw keyboard input. It prints the existing dashboard state and directs the user to the normal CLI commands instead. This keeps CI, pipes, and redirected output safe.\n\n## Git safety\n\nGit information is read through `GitManager`. The UI does not offer silent reset, force, checkout, or destructive cleanup actions. Conflicts are surfaced explicitly.\n\n## Provider safety\n\nThe Models screen reads `ModelManager` and displays provider/model metadata only. It never prints resolved credentials. Use `yasincoder setup` for the provider gateway or `yasincoder setup gemini` for the direct Gemini compatibility path.\n\n## Tests\n\nTUI logic can be tested without an interactive terminal:\n\n```bash\npython -m unittest tests.test_tui -v\n```\n\nThe complete repository suite remains the release gate.\n
